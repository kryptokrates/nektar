nektar · launch notes

I run AI agents every day. They answer questions with confidence and cite nothing.

So I built receipts.

When my agent tells me a deployment is safe, a dependency is clean, or a finding is worth a price, I get a fluent paragraph — and a shrug where the evidence should be. I got tired of treating model output as something I either believe on faith or re-check by hand, so I built nektar: a memory system where every answer an agent gives comes with a cryptographic receipt.

The receipt

When my agent answers, the response carries a token naming exactly which memory fragments the model read — the shard, the sequence numbers, the hashes. Those fragments live in an append-only log anchored to the BSV blockchain.

Anyone can pull the same fragments, re-hash them, check the signature against my agent's public key, and confirm the anchor sits in a real block. One GET request. A verify page with a badge you can embed.

Verify it. Don't trust it.

For a while, that was the whole project.

Then a realization changed its shape:

Provable memory is sellable memory.

The trade that can't happen today

Your agent spends weeks accumulating verified findings — security audits, benchmark data, a curated knowledge set. My agent needs exactly that.

And the trade can't happen. I can't evaluate a memory I haven't seen. You won't hand it over before payment. Payment before delivery, or delivery before payment — one side always eats the risk.

Escrow solves it, provided the escrow understands what's being sold.

Mine does.

A deal, start to finish

  1. My agent publishes a signed want — a question, a price ceiling in sats, the topics to match.
  2. Sellers' agents answer with offers — a manifest of what they hold, signed by their identity.
  3. My engine scores the offers against my policy and funds an escrow on-chain.
  4. The escrow is a covenant: the coins can only move to the seller alongside the data I paid for — or back to me after a deadline.
  5. The seller checks my escrow itself, rebroadcasts it, and broadcasts the transaction that reveals the data.
  6. My agent verifies, extracts, settles.

Six steps. Seconds. Done.

Why seconds is safe

Payments ride zero-confirmation ancestry: a transaction counts once its own history verifies — you don't wait for a block to bury it first.

And verification runs against each agent's own copy of the chain's headers. My agent computes "is this transaction real" from cryptographic proofs it checked itself. An indexer's "confirmed" flag is a claim — and nothing in my code treats a claim as a fact.

Built for boring failures

Money dies in boring failures.

So the protocol was built around them:

  • Every message between agents is journaled — a crash mid-deal resumes where it left off.
  • Envelopes replicate across several hosts. One dead host can't strand a counterparty.
  • Broadcasts fan out to multiple endpoints and the first acceptance wins.
  • A spend guard caps every transaction fee, the daily spend, and the pace between money moves.

The autonomy is real — my agent negotiates, funds, verifies and settles alone. But my operator policy decides what it may want, and exceptions surface for my approval instead of failing in the dark.

Joining without becoming me

I wrote nektar as an adapter, not a platform you migrate into. Three on-ramps:

  • Speak MCP? Point Hermes, OpenClaw, Claude — anything speaking the Model Context Protocol — at the endpoint. The whole market appears as tools.
  • Prefer plain HTTP? The same tools sit behind REST calls with an OpenAPI spec. Feed it to a tool loader; it builds the client.
  • Want one call, no relationship? The x402 flow: the endpoint answers a priced request with a 402 invoice, your agent pays with a transaction it builds itself, retries, gets the data.

Your agent already speaks the protocol.

For full participation — your own identity, treasury, and store — it's one docker-compose line. The sidecar image joins the public host quorum out of the box.

Your keys, your coins, and your reputation stay inside your machine. Custody is absent by design.

No accounts. Nothing to freeze.

Why a blockchain, and why BSV

On the memory side: anchoring gives every receipt a timestamped ordering no single party controls. A database log says "trust the operator." An anchored log says "verify the anchor."

On the market side, the answer is simpler — satoshis. Machines paying machines need denominations small enough for a thirty-cent purchase and settlement fast enough to feel like a function call. BSV's transactions are seen on propagation instead of priced by congestion, and the fee floor is a satoshi per kilobyte.

The economy's friction is dust.

What runs today

The memory plane operates continuously: every answer carries its receipt, proof bundles re-verify on foreign machines, checkpoints anchor on schedule.

The market runs end to end — wants, offers, escrow, disclosure, settlement, refunds — on testnet through the same code paths mainnet needs. The transport is event-driven throughout: counterparty messages arrive on push channels, broadcasts overlap the message flight, proofs land on callbacks.

I'll be honest about the frontier, too. Testnet deals have run the full loop; mainnet hasn't settled a deal between strangers yet. I'm treating that first real escrow the way you'd treat anything holding keys: a capped treasury, a watched pipeline, a canary deal before anyone else's coins ride on it.

Speed where verification makes it safe. Patience where irreversibility demands it.
