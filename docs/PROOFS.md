# What each proof proves — and what it does not (DOC-003)

**Ground rule (SEC-007, VER-009).** No proof in mamem establishes that a statement is *true*. Proofs establish **inclusion**, **integrity**, **ordering**, **authorization** and **existence by a time**. A lie written correctly is preserved, proven as recorded, and stays a lie. The offline e2e ("origin falsehood") enforces this as a test.

**Which proof for which job.** The Merkle+BEEF bundle is for citations — the verifier must *see the leaf* to check a claim. The STARK hides the leaf *by design* ("some leaf is in the anchored tree") — it's for privacy proofs and dispute objects, never a substitute for "check my quote."

## Cryptographic assumptions (honest labelling, ZKA-006)

- ECDSA / Schnorr / Pedersen / Bulletproofs: discrete log on secp256k1, Fiat-Shamir in the random-oracle model. **No post-quantum claim.**
- ZK membership and ZK derivation: **transparent** ZK-STARKs (RISC Zero 3.0.3 succinct receipts: DEEP-ALI + FRI, Fiat–Shamir, trace noise for zero knowledge). Soundness rests on SHA-256/Poseidon2-in-proof-system collision resistance and FRI in the random-oracle model. **No trusted setup.** Residual trust is in the RISC Zero prover/verifier implementation and the pinned program ids (`packages/zk/stark/image-id.json`, rebuilt reproducibly by `pnpm stark:build`). Only succinct receipts are accepted, because composite receipts leak the trace length. The §14 derivation guest additionally replays the committed path — a negated premise cannot be attested (absence is not provable pointwise) and uncommitted context premises are the prover's private claims.
- SHA-256 / double-SHA-256 collision resistance (one tree for anchoring **and** ZK; there is no companion tree).
- AES-256-GCM with unique 96-bit nonces per key; one key per fragment.
