Join mainnet (DOC-004)

The path from "works on testnet" to "holds real money". Every gate below is either executable (a command or drill you run and record) or time/external (it cannot be compressed — no amount of code substitutes). An unchecked time/external gate means not mainnet-ready, regardless of how green the executable column is.

Operating the X1 soak

Two persistent agents with warmed lane stock (node tools/tn-warmup.mjs first), NEKTAR_WATCH_URLS pointed at each other's /watch endpoint, and a deal loop on a jittered cadence: publish a want, wait for settled (or a clean refund), repeat. Record per leg:

  • deal N: <ms> wall times — p50/max regressions are findings, not noise
  • upkeep <ms> lines — a leg over its bound logs exceeded … abandoning;

an abandon is a finding to file, not a pass

  • box submit failed / unreachable rates — one dead host is survivable

(suite R1 proves it), sustained refusal is not

  • reserve medium count over time — exhaustion means a funding-lane leak
  • outbox depth — rows should deliver or dead-letter (~10 attempts), never

accrue

Abort and file when: a deal leg hits its 120s phase bound repeatedly on a healthy network, the same upkeep phase abandons three passes in a row, or an agent writes no sqlite/events for >10min (the suite's [suite quiet <n>s] heartbeat is the same signal, scaled).

Onboarding the X2 operator

Hand them docs/JOIN-TESTNET.md + deploy/hub/ and exactly three things: their own testnet funding key, their own host pair, and the want→offer round-trip drill. Do not share shim config, header sources, machines, or sqlite state — the gate exists to prove a stranger's stack verifies the same proofs on their chosen headers. Success = one deal completes both directions and their status/announce records reconcile with yours.

# reserve + want knobs shipped for the T2/T4 fixes

First live run: one small deal, watch it to settled (or a clean refund), then one more. Only then raise NEKTAR_MAX_SPEND_SATS_PER_DAY.

What the runtime now guarantees (and does not)

Fixed for this gate set — a live buyer's want republishes at each collection boundary while exp remains (want_republished event, same signed record, offers still match); upkeep denominates one dominant UTXO into NEKTAR_RESERVE_OUTS medium outputs so a tree mint and a deal escrow never contend for the same coin; a directory card whose funding tree sits unproven re-announces on a 4-minute keep-alive inside the host's 10-minute FUNDING_PROOF_MS eviction window and stops once the tree proves.

Event layer — deal passes are wake-driven: each agent long-polls its /watch stream and an inbound lane item fires rt.deals() immediately; polling stays only as a bounded fallback (measured: T1 p50 41s→23s on testnet, T3 confirms notifies arrive and the watched path beats the polled one). Every deal leg and each upkeep phase is time-bounded — a hung leg logs its phase name and frees the single-flight instead of silently wedging the loop forever (upkeep(finger) exceeded … abandoning is how a live stall now surfaces).

Finger plane — token bundles are gated on servability before submit: ancestry gaps heal against fetched sources and permanently-gapped bundles skip instead of resubmitting frozen-invalid beef forever (a poisoned journal starved live deals until evicted). EF-parsed sparse-output stubs are detached before BEEF serialization — the null.satoshis crash class. The full-chain re-serve amortizes to bounded batches per upkeep so a deep history can't park a pass for minutes.

Not guaranteed — counterparty uptime, mempool/mining cadence on main, host-side admission policy beyond the vendored engines, and every time/external gate above. Zero-conf progression stays bounded by verified ancestry; nothing here relaxes a proof check to buy latency.
