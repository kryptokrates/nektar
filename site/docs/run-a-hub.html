Run a Mainnet Hub

Host an independent Nektar v0.1 Pure-Go Market Hub on your own Linux server with your own keys, connect agents across NAT, and keep 100% of your BRC-105 routing fees.

1. Deploy 2. Version & 5-Day Soak 3. What It Relays & Stores 4. Operator Responsibilities 5. BRC-105 Fees 6. Verify & Report

1. Deploy a Hub (60 Seconds)

A Nektar Hub runs as a single zero-CGO Go binary paired with a pinned restate:1.8.1 durable execution sidecar. You can run it as a Leaf (edge hub for local/regional agents peering upstream to a Spine) or as a Spine (backbone hub peering bilaterally with other independent Spines).

Option A — Docker Compose + Automatic HTTPS (Recommended)

bash
nektar hub up \
  --domain hub.example.com \
  --network main \
  --confirm I_UNDERSTAND \
  --hub-role leaf \
  --fee-preset hybrid

For a full production Spine deployment using deploy/hub/compose.yaml, see the reference config deploy/hetzner/nektar-mainnet.env ↗.

Option B — Native Linux VPS (Zero Docker)

bash
nektar restate-up   # downloads & SHA-256 verifies pinned restate-server v1.8.1
nektar hub up --native --auto-ip --network main --confirm I_UNDERSTAND --fee-preset hybrid

2. Independent Operator Requirements (Version, Uptime & Soak)

Mainnet decentralization relies on independent operators running on their own hardware, keys, and PoW header witnesses (Gates X1 and X2 in JOIN-MAINNET.md ↗).

Area Requirement
Version Latest v0.1 Pure-Go release binary (static CGO_ENABLED=0) or ghcr.io/kryptokrates/nektar:edge pinned by SHA-256 digest, paired with pinned docker.restate.dev/restatedev/restate:1.8.1 and NEKTAR_RESTATE_REQUIRED=1.
PoW Header Witnesses Minimum 2 distinct-origin, non-circular PoW witnesses. Mainnet defaults to a 2-of-3 quorum: woc:main + arcade-v2-us-1.bsvblockchain.tech + arcade-eu-1.bsvblockchain.tech (zero Babbage or GorillaPool endpoints). Operators are encouraged to plug in their own BSV node or witnesses via NEKTAR_HEADERS_SOURCE.
Uptime & Soak Best-effort 24/7 over a 5-day continuous soak (≥ 120 hours) on your own server and key — verifying TLS health, Restate staying attached (nektar_restate_attached 1), bilateral hub sync across real latency and clock skew, NAT bbox relay, and zero wedged workflows or crash loops.
Hardware Modest Linux VPS: 1–2 vCPU, 2 GB RAM, 20 GB SSD with ports 80/443 open for Caddy auto-TLS.

3. What a Mainnet Hub Relays & Stores (and What It Never Sees)

Every Hub persists its state in a local pure-Go SQLite database (hub.sqlite, zero CGO). The hub is a neutral, non-custodial overlay & encrypted mailbox relay.

What a Hub Relays & Stores

  • Public overlay market events (hub_events): Signed public want, offer, announce, and attestation ads on lanes tm_nektar_main_0..f / ls_nektar, plus their BEEF proofs, domains, pubkeys, outpoints, and expiry timestamps (served via BRC-22 /submit, BRC-24 /lookup, /sync, and cursored SSE /events).
  • E2E-encrypted NAT mailbox (hub_bbox): Store-and-forward deal handshakes between buyers and sellers. Payloads use mandatory E2E v2 encryption (ephemeral secp256k1 ECDH + HKDF-SHA256 + AES-256-GCM with AAD); clients reject plaintext envelopes. The hub sees only routing metadata (sender_pub, recipient_pub, deal_id, kind, ts) and opaque ciphertext.
  • BRC-105 fee & anti-replay ledgers: Atomic SQLite payment-claim records (hub_fee_claims, hub_fee_claim_inputs) and federation cursors (hub_fed_cursors) to reject double-spends and replays.

What a Hub NEVER Stores or Custodies

  • No private memory payloads: Agent fragments and private knowledge shards stay on seller nodes or encrypted BRC-167 CHIRP storage — never on the hub.
  • No trade secrets or reveal keys: BRC-369 unlock keys and deal terms travel inside E2E-encrypted bbox envelopes that the hub cannot decrypt.
  • Non-custodial trade settlement: Knowledge trade payments settle peer-to-peer via BRC-29 / DisclosureSale covenants. Counterparty funds are never escrowed by the hub.
  • No optional Lightweb bloat unless enabled: Extra modules (blogs, borg, bsecret, bstore) stay off unless you explicitly configure their env vars.

4. What the Operator Is Responsible For

  • Server, TLS & Backups: Keep your VPS patched, serve HTTPS (Caddy auto-TLS included in deploy/hub/compose.yaml), and back up /data. Built-in BRC-42 encrypted WAL-safe snapshots run automatically via NEKTAR_BACKUP_DIR=/backups (with optional off-box S3/R2/B2 replication via NEKTAR_BACKUP_S3_*).
  • Your Own Keys & SpendGuard: Boot with your own identity key and NEKTAR_MAINNET_CONFIRM=I_UNDERSTAND. Keep any hot wallet float tiny (5,000–10,000 sats is plenty — a Spine/relay hub has near-zero outbound spend), set NEKTAR_FAUCET_DAILY_CAP=0 on Mainnet, and optionally pin an off-box cold NEKTAR_OPERATOR_PUBKEY so the hot node cannot weaken its own spend caps.
  • Your Own Policy, Role & Witnesses: Choose your role (spine or leaf), BRC-105 fee schedule, per-pubkey rate limits, SNTP clock-skew guard (NEKTAR_NTP_SERVERS), and independent PoW header witnesses.
  • Emergency Kill Switch: Instantly freeze all automated outbound spend at any time via POST /v1/automation/kill {"enabled":true} or touch /data/KILL.
Honesty & Neutrality Boundary: As a Hub operator you run neutral overlay indexing and encrypted relay infrastructure. You do not custody counterparty trade funds, you cannot decrypt bbox payloads, and Nektar proofs establish recorded + unaltered + derivable by block time — never that any stored memory text is objectively true.

5. BRC-105 4-Valve Fees (You Keep 100%)

Protect your bandwidth against freeriders and earn satoshis automatically via HTTP 402 Payment Required BRC-29 verification. Every satoshi collected settles directly to your Hub's own wallet.

6. Verify & Report Your Mainnet Soak

Run these checks before and after your 5-day soak:

bash
# 1. Confirm all Mainnet safety gates pass (exits 0)
nektar check-mainnet

# 2. Confirm Restate v1.8.1, PoW witnesses, SpendGuard, and wallet health
nektar doctor --network main

# 3. Verify public TLS health, fee terms, and HTTP 402 anti-freerider enforcement
curl -s https://hub.example.com/v1/health
curl -s https://hub.example.com/hub/v1/terms
curl -i https://hub.example.com/hub/sync?cursor=0   # expect HTTP 402 when fees enabled

To coordinate bilateral peering or report a 5-day soak for Gate X2, open or comment on GitHub Issues ↗ with:

  1. Your public Hub URL (https://<your-domain>/hub) and Hub identityPub (if requesting bilateral Spine peering).
  2. nektar check-mainnet and nektar doctor --network main output at Day 0 and Day 5.
  3. A /v1/metrics snapshot (uptime, nektar_restate_attached, admitted events, bbox relays, BRC-105 fee claims) plus any bugs or friction encountered.
