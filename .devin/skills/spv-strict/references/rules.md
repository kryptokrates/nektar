# rules — `spv/*`, strict

Each rule: the violation, the doctrine it breaks (D-numbers in
doctrine.md), how to detect it, default severity, and the fix seam in
this repo. Severity rises one step when the path moves money or durable
state; it never drops below MED.

## Trust half — believed, not computed

| `spv/hint-as-verified`  | A status string (MINED, REJECTED, DOUBLE_SPEND_ATTEMPTED, SEEN) reaches a 'tx' emit, a durable state write or a money decision. ## Latency half — waited for, though provable

| Rule                             | Violation                                                                                                                                           | Doctrine   | Detect                                                                                                                                                         | Sev  | Fix seam                                                                                     |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- | -------------------------------------------------------------------------------------------- |
| `spv/block-wait`                 | A deal-path step sleeps, polls or defers until a block, when proven stock or carried ancestry would have served. Money waiting for depth is exempt. | D4, D5, D9 | every `proven` gate, `'no funding slot'`, `'not proven yet'`, warmup loop, `waitFor(…mined)` reachable from want → offer → escrow → disclosure                 | HIGH | stock ahead (`ensureTrees` low-water), one-hop ancestry (`anchoredTree`), proof updates (D6) |
| `spv/unstocked-lane`             | A lane can reach zero proven slots while the agent holds funds: mint-on-demand, refill starting at empty, a single mint in flight.                  | D5         | `ensureTrees` `lowWater` / `maxUnproven` per kind; first-boot path for a new identity                                                                          | HIGH | refill while a full tree of proven stock remains; provision stock in the funding transaction |
| `spv/proofless-funding`          | A funding output is handed on without the merkle path its transaction has, so everything built on it looks unanchored.                              | D3, D4     | where `FundingOut.tx` is produced: `Transaction.fromHex`, wallet `listOutputs` BEEF, `discoverUtxos`, `importFundingTx` → is `merklePath` attached when mined? | HIGH | attach from `TxStore` / `proofLookup` at the funder seam; verify against the tracker         |
| `spv/beefless-handoff`           | A counterparty or internal consumer is given a txid or raw tx where BEEF/EF was available.                                                          | D3         | handoff sites not using `txWire`                                                                                                                               | MED  | `txWire` ladder                                                                              |
| `spv/proof-withheld-until-mined` | An object is held back until its own proof exists although its signature and ancestry already verify and no value depends on it.                    | D6         | publish gated on `merklePath` of the object itself                                                                                                             | HIGH | publish now, republish with the BUMP                                                         |
| `spv/refetch-held-evidence`      | Code re-asks the network for a tx, path or header it already holds or was just handed.                                                              | D3         | parent walks before checking the subject's own proof; header lookups per item                                                                                  | MED  | check own proof first; `TxStore`; header cache                                               |
| `spv/reimport-spent`             | An output is (re)imported without checking this instance already spent it, creating double-spend attempts on restart.                               | D8         | import paths (`NEKTAR_FUND_TXIDS`, discovery, `addOwned`) vs the wallet's/ledger's own spend records                                                           | HIGH | first-party spent set consulted before import                                                |
| `spv/opaque-wait`                | A wait reports no cause ("no funding slot") so nothing can tell stock-out from fault.                                                               | D9         | error strings and `doctor`/`fund` output                                                                                                                       | MED  | report per lane: proven slots, unproven trees, what each waits on                            |

## Reading the result

- A `spv/block-wait` finding always names its cause as one of: missing
  stock, missing carried evidence, or a deliberate value-depth rule. The
  third is not a finding.
- Removing a wait by weakening a check converts a latency finding into a
  trust finding. That is never a fix.
- A lane that depends on a third-party codec's stricter rule (the
  vendored host modules) is fixed by stocking, not by forking the rule.
